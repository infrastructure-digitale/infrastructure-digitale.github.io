CHAPITRE01

Introduction à l'automatisation

Ce que tu fais trois fois à la main, un script peut le faire mille fois sans se tromper.

Objectifs du chapitre

  • Expliquer l'intérêt de l'automatisation pour un technicien

« Un bon administrateur est paresseux : il automatise tout ce qui se répète. »

1.1Pourquoi automatiser ?

Créer 40 comptes utilisateurs, sauvegarder chaque soir 10 serveurs, vérifier que 200 équipements répondent au ping… À la main, c'est long, ennuyeux et source d'erreurs. Un script fait ces tâches automatiquement, toujours de la même façon.

iDéfinition

Un script est un fichier texte qui contient une suite d'instructions exécutées les unes après les autres par un interpréteur (Bash, PowerShell, Python). Il automatise une tâche répétitive.

À la mainAvec un script
40 comptes créés en 2 heures40 comptes créés en 10 secondes, à partir d'un fichier CSV
Fautes de frappe, oublisLe même résultat à chaque exécution
Dépend de la mémoire du technicienLa procédure est écrite, partageable et réutilisable
Impossible la nuit ou le week-endPlanifié automatiquement (cron, Planificateur de tâches)
≈Analogie

Un script, c'est une recette de cuisine écrite pour un robot cuisinier. Tu l'écris une fois avec précision ; ensuite le robot la refait autant de fois que tu veux, à l'heure que tu veux, sans oublier le sel.

1.4Penser avant de coder : l'algorithme

Avant d'écrire un script, on décrit les étapes en français : c'est l'algorithme (ou pseudo-code).

Les trois briques de tout algorithme, dans tous les langages :

Séquence

Les instructions s'exécutent dans l'ordre, l'une après l'autre.

Condition

« Si le serveur répond, alors… sinon… » : if.

Boucle

« Pour chaque serveur de la liste… » : for, while.

1.5Les règles d'un bon script

  • Commenter : expliquer le but du script et des parties délicates (#).
  • Tester en labo avant la production, d'abord sur une seule machine.
  • Gérer les erreurs : que se passe-t-il si le fichier n'existe pas ou si le serveur ne répond pas ?
  • Journaliser : écrire ce qui a été fait dans un fichier log.
  • Ne jamais écrire un mot de passe en clair dans un script.
!Attention

Un script exécute exactement ce qui est écrit, très vite, sur toutes les machines. Une erreur dans une commande de suppression peut effacer des centaines de fichiers en une seconde. On teste toujours sur un jeu d'essai.

2.1Le terminal et l'invite

Bash (Bourne Again SHell) est le shell par défaut de la plupart des distributions Linux. L'invite (prompt) indique l'utilisateur, la machine et le dossier courant :

stagiaire@srv-web:~$      # utilisateur normal, dans son dossier personnel (~)
root@srv-web:/etc#        # administrateur (root), dans /etc ; le # signale les pleins droits

Une commande s'écrit : commande -options arguments. Exemple : ls -l /etc.

2.6Les permissions

Chaque fichier a des droits pour trois catégories : le propriétaire (u), le groupe (g), les autres (o). Trois droits : r (lire, 4), w (écrire, 2), x (exécuter, 1).

ls -l sauvegarde.sh
-rwxr-x--- 1 ahmed admins 812 nov 13 10:02 sauvegarde.sh
chmod 750 sauvegarde.sh      # rwx pour le propriétaire, r-x pour le groupe, rien pour les autres
chmod +x sauvegarde.sh       # ajoute le droit d'exécution
sudo chown ahmed:admins sauvegarde.sh   # change le propriétaire et le groupe
✓Astuce : les valeurs à connaître

755 = scripts et dossiers publics · 644 = fichiers texte · 700 = privé · 600 = fichier secret (clé SSH). Jamais 777 : tout le monde pourrait modifier le fichier.

★À retenir

• Chemins absolus (/…) et relatifs ; . .. ~.
• > écrase, >> ajoute, 2> erreurs, | enchaîne les commandes.
• grep, wc, sort, uniq, cut, find pour filtrer.
• Permissions rwx pour u/g/o, en chiffres (r=4, w=2, x=1) : chmod 750.

3.1Premier script

BASH 
#!/bin/bash
# bonjour.sh — premier script : affiche un message et la date
echo "Bonjour, je suis le serveur $(hostname)"
echo "Nous sommes le $(date +%d/%m/%Y)"
chmod +x bonjour.sh     # rendre le script exécutable
./bonjour.sh            # l'exécuter (ou : bash bonjour.sh)

Nous sommes le 13/11/2026
iLe shebang

La première ligne #!/bin/bash s'appelle le shebang : elle indique quel interpréteur doit exécuter le fichier. $(commande) remplace la commande par son résultat (substitution de commande).

3.5Fonctions et codes de retour

#!/bin/bash
LOG="/var/log/mes_scripts.log"

journal() {                                  # définition d'une fonction
  echo "$(date '+%F %T') - $1" >> "$LOG"
}

verifier_service() {
  if systemctl is-active --quiet "$1"; then
    journal "$1 fonctionne";  return 0
  else
    journal "$1 ARRÊTÉ, redémarrage"; systemctl restart "$1"; return 1
  fi
}

for s in nginx ssh cron; do verifier_service "$s"; done

3.6Exemple complet : sauvegarde avec rotation

BASH 
#!/bin/bash
# sauvegarde.sh — archive /var/www chaque jour et garde 7 jours d'historique
SOURCE="/var/www"
DEST="/backup"
DATE=$(date +%F)                               # ex. 2026-11-13
ARCHIVE="$DEST/www-$DATE.tar.gz"

mkdir -p "$DEST"
if tar -czf "$ARCHIVE" "$SOURCE" 2>/dev/null; then
  echo "$(date '+%F %T') OK $ARCHIVE ($(du -h "$ARCHIVE" | cut -f1))" >> "$DEST/sauvegarde.log"
else
  echo "$(date '+%F %T') ERREUR sauvegarde" >> "$DEST/sauvegarde.log"
  exit 1
fi
find "$DEST" -name "www-*.tar.gz" -mtime +7 -delete   # rotation : supprime après 7 jours

4.5Exécuter un script : la stratégie d'exécution

Par défaut, Windows bloque souvent les scripts .ps1. La stratégie d'exécution (execution policy) le contrôle :

from datetime import datetime

RESEAU = "192.168.1.0/24"

def ping(ip):
    opt = "-n" if platform.system() == "Windows" else "-c"
    r = subprocess.run(["ping", opt, "1", str(ip)], capture_output=True)
    return str(ip), r.returncode == 0

hotes = list(ipaddress.ip_network(RESEAU).hosts())
with ThreadPoolExecutor(max_workers=50) as ex:      # 50 pings en parallèle

    w.writerow(["ip", "etat"])

TP 1Bash : sauvegarde automatique avec rotation

Objectifs : archiver un dossier avec la date dans le nom, journaliser, supprimer les archives de plus de 7 jours, planifier avec cron.

Étapes

  1. Créer un dossier de test : mkdir -p ~/site && echo "index" > ~/site/index.html.
  2. Écrire ~/scripts/sauvegarde.sh qui crée ~/backup/site-AAAA-MM-JJ_HHhMM.tar.gz.
  3. Écrire une ligne dans ~/backup/sauvegarde.log : date, nom de l'archive, taille, OK ou ERREUR.
  4. Supprimer les archives de plus de 7 jours (find … -mtime +7 -delete).
  5. Le script accepte un argument facultatif : le dossier à sauvegarder (par défaut ~/site). Si le dossier n'existe pas : message d'erreur et code de sortie 1.
  6. Planifier le script tous les jours à 23 h 30 avec crontab -e, puis vérifier avec crontab -l.
Solution — TP 1
#!/bin/bash
# sauvegarde.sh — usage : ./sauvegarde.sh [dossier]
set -u
SOURCE="${1:-$HOME/site}"                  # argument 1 ou valeur par défaut
DEST="$HOME/backup"
LOG="$DEST/sauvegarde.log"
HORO=$(date +%F_%Hh%M)
ARCHIVE="$DEST/$(basename "$SOURCE")-$HORO.tar.gz"

if [ ! -d "$SOURCE" ]; then
  echo "Erreur : le dossier $SOURCE n'existe pas" >&2
  exit 1
fi
mkdir -p "$DEST"

if tar -czf "$ARCHIVE" -C "$(dirname "$SOURCE")" "$(basename "$SOURCE")"; then
  TAILLE=$(du -h "$ARCHIVE" | cut -f1)
  echo "$(date '+%F %T') OK $ARCHIVE $TAILLE" >> "$LOG"
else
  echo "$(date '+%F %T') ERREUR $SOURCE" >> "$LOG"
  exit 2
fi

find "$DEST" -name "*.tar.gz" -mtime +7 -delete
echo "Sauvegarde terminée : $ARCHIVE ($TAILLE)"
chmod 750 ~/scripts/sauvegarde.sh
crontab -e
30 23 * * * /home/stagiaire/scripts/sauvegarde.sh >> /home/stagiaire/backup/cron.log 2>&1

Points clés : ${1:-valeur} donne une valeur par défaut ; -C évite de stocker le chemin complet dans l'archive ; dans cron on écrit des chemins absolus (cron n'a pas le même environnement que ton terminal) ; 2>&1 envoie aussi les erreurs dans le log.

TP 2Bash : créer des comptes Linux à partir d'un fichier

Objectifs : lire un fichier ligne par ligne, créer comptes et groupes, gérer les comptes déjà existants, produire un compte rendu.

Fichier comptes.txt (login:groupe) :

salaoui:rh
kbennani:compta
yidrissi:info
salaoui:rh

Étapes

  1. Vérifier que le script est lancé en root ($EUID -eq 0), sinon quitter.
  2. Pour chaque ligne : créer le groupe s'il n'existe pas (getent group, groupadd).
  3. Si le compte existe déjà (id), afficher « déjà existant » et passer au suivant.
  4. Sinon : useradd -m -g groupe -s /bin/bash login, mot de passe initial et obligation de le changer (chage -d 0).
  5. Afficher à la fin le nombre de comptes créés et ignorés.
Solution — TP 2
#!/bin/bash
# creer_comptes.sh — usage : sudo ./creer_comptes.sh comptes.txt
FICHIER="${1:?Usage : $0 fichier}"
[ "$EUID" -eq 0 ] || { echo "À lancer avec sudo"; exit 1; }
[ -f "$FICHIER" ] || { echo "Fichier introuvable"; exit 2; }
read -s -p "Mot de passe initial : " MDP; echo
crees=0; ignores=0

while IFS=: read -r login groupe; do
  [ -z "$login" ] && continue                       # ignore les lignes vides
  getent group "$groupe" > /dev/null || groupadd "$groupe"
  if id "$login" &> /dev/null; then
    echo "[=] $login déjà existant"; ignores=$((ignores + 1))
  else
    useradd -m -g "$groupe" -s /bin/bash "$login"
    echo "$login:$MDP" | chpasswd
    chage -d 0 "$login"                              # changement à la 1re connexion
    echo "[+] $login créé dans $groupe"; crees=$((crees + 1))
  fi
done < "$FICHIER"
echo "Bilan : $crees créé(s), $ignores ignoré(s)"
[+] salaoui créé dans rh
[+] kbennani créé dans compta
[+] yidrissi créé dans info
[=] salaoui déjà existant
Bilan : 3 créé(s), 1 ignoré(s)

Points clés : IFS=: découpe chaque ligne sur les deux-points ; read -s masque la saisie du mot de passe ; le test avec id rend le script idempotent (on peut le relancer sans erreur).

TP 3PowerShell : rapport d'inventaire HTML

Objectifs : collecter les informations d'un poste (système, mémoire, disques, IP, services arrêtés) et produire une page HTML lisible.

Étapes

  1. Récupérer nom de la machine, version de Windows, mémoire totale et date du dernier démarrage (Get-CimInstance Win32_OperatingSystem, Win32_ComputerSystem).
  2. Lister les disques avec taille, espace libre et pourcentage libre (Win32_LogicalDisk, DriveType=3).
  3. Lister les adresses IPv4 (Get-NetIPAddress), sans l'adresse 127.0.0.1.
  4. Lister les services automatiques arrêtés.
  5. Assembler un rapport avec ConvertTo-Html et l'enregistrer dans C:\Rapports\NOM-DATE.html, puis l'ouvrir.
Solution — TP 3
# inventaire.ps1
$os  = Get-CimInstance Win32_OperatingSystem
$cs  = Get-CimInstance Win32_ComputerSystem
$dossier = "C:\Rapports"; New-Item $dossier -ItemType Directory -Force | Out-Null

$systeme = [PSCustomObject]@{
    Machine      = $env:COMPUTERNAME
    Windows      = $os.Caption
    'RAM (Go)'   = [math]::Round($cs.TotalPhysicalMemory / 1GB, 1)
    Demarrage    = $os.LastBootUpTime
}
$disques = Get-CimInstance Win32_LogicalDisk -Filter "DriveType=3" | ForEach-Object {
    [PSCustomObject]@{ Lecteur = $_.DeviceID
        'Taille (Go)' = [math]::Round($_.Size / 1GB, 1)
        'Libre (Go)'  = [math]::Round($_.FreeSpace / 1GB, 1)
        'Libre (%)'   = [math]::Round($_.FreeSpace / $_.Size * 100) }
}
$ips = Get-NetIPAddress -AddressFamily IPv4 | Where-Object IPAddress -ne "127.0.0.1" |
       Select-Object InterfaceAlias, IPAddress, PrefixLength
$services = Get-Service | Where-Object { $_.StartType -eq 'Automatic' -and $_.Status -ne 'Running' } |
       Select-Object Name, DisplayName, Status

$style = "<style>body{font-family:Segoe UI}table{border-collapse:collapse}td,th{border:1px solid #ccc;padding:4px 8px}th{background:#1B2A4A;color:#fff}</style>"
$html = @(
  $systeme  | ConvertTo-Html -Fragment -As List -PreContent "<h2>Système</h2>"
  $disques  | ConvertTo-Html -Fragment -PreContent "<h2>Disques</h2>"
  $ips      | ConvertTo-Html -Fragment -PreContent "<h2>Adresses IP</h2>"
  $services | ConvertTo-Html -Fragment -PreContent "<h2>Services automatiques arrêtés</h2>"
)
$fichier = "$dossier\$env:COMPUTERNAME-$(Get-Date -Format yyyy-MM-dd).html"
ConvertTo-Html -Head $style -Body $html -Title "Inventaire $env:COMPUTERNAME" | Out-File $fichier -Encoding utf8
Start-Process $fichier

Points clés : Get-CimInstance interroge WMI (matériel, système) ; on construit des objets propres avec [PSCustomObject] ; -Fragment produit seulement le tableau, qu'on assemble dans une page complète.

# comptes_locaux.ps1
$mdp = Read-Host "Mot de passe initial" -AsSecureString

TP 5Python : scanner un réseau

Objectifs : recevoir un réseau en argument, pinger tous les hôtes en parallèle, tester les ports 22 et 80 sur les hôtes actifs, produire un CSV.

Étapes

  1. Utiliser argparse pour recevoir le réseau : python scan.py 192.168.1.0/24.
  2. Valider le réseau avec ipaddress (message clair si l'adresse est invalide).
  3. Pinger tous les hôtes avec ThreadPoolExecutor.
  4. Pour chaque hôte actif, tester les ports 22 et 80 avec socket.
  5. Enregistrer scan_AAAAMMJJ.csv (ip, ssh, http) et afficher le résumé.
Solution — TP 5
#!/usr/bin/env python3
"""scan.py — usage : python scan.py 192.168.1.0/24"""
import argparse, csv, ipaddress, platform, socket, subprocess, sys
from concurrent.futures import ThreadPoolExecutor
from datetime import datetime

def ping(ip):
    opt = "-n" if platform.system() == "Windows" else "-c"
    r = subprocess.run(["ping", opt, "1", "-w" if opt == "-n" else "-W", "1000" if opt == "-n" else "1", ip],
                       capture_output=True)
    return r.returncode == 0

def port_ouvert(ip, port):
    try:
        with socket.create_connection((ip, port), timeout=0.5):
            return True
    except OSError:
        return False

parser = argparse.ArgumentParser(description="Scanner de réseau du labo")
parser.add_argument("reseau", help="exemple : 192.168.1.0/24")
args = parser.parse_args()
try:
    reseau = ipaddress.ip_network(args.reseau, strict=False)
except ValueError:
    sys.exit(f"Réseau invalide : {args.reseau}")

hotes = [str(h) for h in reseau.hosts()]
with ThreadPoolExecutor(max_workers=64) as ex:
    etats = dict(zip(hotes, ex.map(ping, hotes)))
actifs = [ip for ip, ok in etats.items() if ok]

fichier = f"scan_{datetime.now():%Y%m%d}.csv"
with open(fichier, "w", newline="") as f:
    w = csv.writer(f, delimiter=";")
    w.writerow(["ip", "ssh", "http"])
    for ip in actifs:
        ssh, web = port_ouvert(ip, 22), port_ouvert(ip, 80)
        w.writerow([ip, ssh, web])
        print(f"{ip:15}  SSH:{'oui' if ssh else 'non':3}  HTTP:{'oui' if web else 'non'}")
print(f"\n{len(actifs)} hôte(s) actif(s) sur {len(hotes)} — rapport : {fichier}")

Points clés : argparse génère automatiquement l'aide (-h) ; strict=False accepte 192.168.1.15/24 ; le ping en parallèle réduit le scan d'un /24 de plusieurs minutes à quelques secondes ; le CSV avec ; s'ouvre directement dans Excel en français.

TP 6Python : sauvegarder la configuration de switchs Cisco

Objectifs : lire un inventaire CSV, se connecter en SSH à chaque équipement avec Netmiko, enregistrer la configuration et créer un VLAN partout.

Étapes

  1. Sur chaque switch : hostname, domaine, compte local privilège 15, clés RSA, SSH v2, adresse IP de gestion (voir module Sécurité, TP 1). Vérifier ssh admin@10.0.0.2 depuis le PC.
  2. Créer equipements.csv (nom, ip, type = cisco_ios).
  3. Écrire le script : demander utilisateur et mot de passe (getpass), boucler sur l'inventaire.
  4. Pour chaque switch : show running-config → fichier configs/NOM_DATE.cfg.
  5. Option --vlan 30 --nom INVITES : créer le VLAN sur tous les switchs puis save_config().
  6. Gérer les erreurs (équipement éteint, mauvais mot de passe) sans arrêter le script ; bilan final.
Solution — TP 6
#!/usr/bin/env python3
"""configs.py — sauvegarde des configurations et création de VLAN (Netmiko)"""
import argparse, csv, getpass, pathlib
from datetime import date
from netmiko import ConnectHandler
from netmiko.exceptions import NetmikoAuthenticationException, NetmikoTimeoutException

p = argparse.ArgumentParser()
p.add_argument("--inventaire", default="equipements.csv")
p.add_argument("--vlan", type=int, help="numéro de VLAN à créer")
p.add_argument("--nom", default="NOUVEAU", help="nom du VLAN")
args = p.parse_args()

user = input("Utilisateur SSH : ")
mdp = getpass.getpass("Mot de passe : ")
dossier = pathlib.Path("configs"); dossier.mkdir(exist_ok=True)
ok, ko = [], []

with open(args.inventaire) as f:
    for eq in csv.DictReader(f):
        try:
            with ConnectHandler(device_type=eq["type"], host=eq["ip"],
                                username=user, password=mdp, timeout=10) as conn:
                cfg = conn.send_command("show running-config")
                (dossier / f"{eq['nom']}_{date.today()}.cfg").write_text(cfg)
                if args.vlan:
                    conn.send_config_set([f"vlan {args.vlan}", f"name {args.nom}"])
                    conn.save_config()
            ok.append(eq["nom"]); print(f"[OK]  {eq['nom']}")
        except NetmikoAuthenticationException:
            ko.append(eq["nom"]); print(f"[ERR] {eq['nom']} : identifiants refusés")
        except NetmikoTimeoutException:
            ko.append(eq["nom"]); print(f"[ERR] {eq['nom']} : injoignable")

print(f"\nBilan : {len(ok)} réussi(s), {len(ko)} en échec {ko if ko else ''}")
python configs.py                          # sauvegarde seule
python configs.py --vlan 30 --nom INVITES  # sauvegarde + VLAN 30 sur tous les switchs

Vérification : sur un switch, show vlan brief affiche le VLAN 30 INVITES ; le dossier configs contient un fichier par équipement. Points clés : with ConnectHandler(...) ferme la session même en cas d'erreur ; on capture des exceptions précises pour un bilan clair ; le mot de passe n'apparaît jamais dans le code.

function Sauver-Dossier {
    param(
        [Parameter(Mandatory)] [string]$Source,
        [Parameter(Mandatory)] [string]$Destination
    )
    $log = "C:\Logs\sauvegarde.log"
    try {
        Copy-Item $Source $Destination -Recurse -Force -ErrorAction Stop
        Add-Content $log "$(Get-Date -Format 'yyyy-MM-dd HH:mm') OK $Source -> $Destination"
    } catch {
        Add-Content $log "$(Get-Date -Format 'yyyy-MM-dd HH:mm') ERREUR $Source : $($_.Exception.Message)"
    }
}
